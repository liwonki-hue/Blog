예전에는 웹사이트 하나를 외주로 맡기면 수백만 원이 들었다. 지금은 AI 에이전트에게 "이런 웹사이트를 만들어 줘"라고 말로 지시하는 것만으로 꽤 괜찮은 웹사이트를 직접 만들고, 인터넷에 배포까지 할 수 있다. 이 글은 코딩을 전혀 몰라도 클로드(Claude)에게 요청하는 방식으로 나만의(또는 회사의) 웹사이트를 처음부터 끝까지 만들어 보는 글이다.

> 이 글은 두 편으로 이어지는 시리즈의 **1편**이다. 웹사이트 만들기를 먼저 익히고 나면, 다음 글 [나만의 챗봇 만들기]({{< ref "나만의-챗봇-만들기" >}})에서 같은 방식으로 AI 챗봇을 만들어 본다.

## 1부. 시작하기 전에 알아야 할 것들

### 1-1. 에이전트란 무엇인가

흔히 쓰는 "AI 챗봇"은 질문을 하면 답을 **말해 주는** 역할에 그친다. 반면 **에이전트**는 목표를 주면 그 목표를 이루기 위해 스스로 생각하고, 필요한 행동을 직접 수행한다. 클로드 코드 같은 코딩 전용 에이전트에게 "이런 기능이 있는 웹사이트를 만들어 줘"라고 요청하면, 에이전트는 코드를 어떻게 짜면 되는지 설명만 하는 게 아니라 **직접 코드를 작성하고, 실행해 보고, 문제가 있으면 스스로 고치는 것**까지 한다.

과거에는 개발자가 한 줄 한 줄 코드를 직접 작성해야 했다. 지금은 사람이 "무엇을 원하는지"만 명확하게 전달하면, 에이전트가 실제 구현을 전담한다.

### 1-2. 바이브 코딩이란

이렇게 세세한 코드를 직접 들여다보지 않고, 원하는 결과를 말로 지시하면서 에이전트와 함께 만들어 가는 개발 방식을 **바이브 코딩**(Vibe Coding)이라고 부른다. 이 용어는 오픈AI의 공동 창립자였던 안드레 카파시가 처음 쓴 말로 알려져 있다. 핵심은 이것이다. 코딩을 몰라도, 나이가 많든 적든, 컴퓨터에 익숙하지 않아도 **명확하게 지시할 수 있으면** 쓸 만한 웹사이트나 서비스를 만들 수 있다.

### 1-3. 서버와 배포

웹사이트를 만들고 나면 "이 웹사이트를 다른 사람도 볼 수 있게 하려면 어떻게 해야 하나"라는 문제가 남는다. 여기서 두 가지 개념을 알아야 한다.

**서버**는 요청을 받으면 응답을 돌려주는 컴퓨터(또는 프로그램)다. 음식점에서 "메뉴판 주세요"라고 하면 서빙하는 분이 메뉴판을 갖다 주는 것과 같다. 우리가 브라우저에 어떤 주소를 입력하면, 그 주소를 가진 컴퓨터(서버)에 "이 페이지를 보여 줘"라는 요청이 가고, 서버가 그 내용을 응답으로 돌려준다.

에이전트가 막 만들어 준 웹사이트는 보통 `localhost:3000` 같은 주소로 뜨는데, 이건 **내 컴퓨터 안에서만** 보이는 주소다. 다른 사람이 접속하려면 이 웹사이트가 **24시간 켜져 있는 서버**에 올라가 있어야 한다. 내 노트북을 24시간 켜 둘 수는 없으니, 이 역할을 대신해 주는 서비스가 필요하다. 이렇게 완성된 코드를 인터넷에서 접속 가능한 서버에 올리는 과정을 **배포**(Deploy)라고 한다.

과거에는 서버를 직접 빌리고(AWS 등) 설정하는 과정이 꽤 까다로웠다. 지금은 **Vercel** 같은 서비스가 이 과정을 거의 자동화해 준다. 코드 저장소(GitHub)만 연결해 두면, 코드가 바뀔 때마다 자동으로 다시 배포까지 해 준다.

### 1-4. GitHub — 코드를 보관하는 클라우드

에이전트가 작성한 코드는 어딘가에 안전하게 저장해 둬야 한다. 구글 드라이브에 문서를 올려 두듯, 코드를 올려 두고 변경 이력까지 관리해 주는 서비스가 **GitHub**다. 코드를 GitHub에 올려 두면 다음과 같은 이점이 있다.

- 내 컴퓨터에 문제가 생겨도 코드를 잃어버리지 않는다.
- Vercel 같은 배포 서비스와 연결해서, 코드가 바뀔 때마다 자동으로 재배포되게 만들 수 있다.
- 작업 이력이 남아서, 누가 언제 무엇을 바꿨는지 추적할 수 있다.

GitHub에서 코드를 저장하는 하나의 공간을 **저장소**(Repository)라고 부른다.

## 2부. 실전 — 클로드로 나만의 웹사이트 만들기

### 준비물

| 항목 | 설명 |
|---|---|
| **클로드 코드(Claude Code)** | 터미널에서 클로드에게 코드를 작성·실행시킬 수 있는 도구. |
| **GitHub 계정** | 완성된 코드를 저장하고 배포 서비스와 연결하는 데 쓴다. |
| **Vercel 계정** | 완성된 웹사이트를 무료로 인터넷에 올려 주는 배포 서비스. GitHub 계정으로 바로 가입할 수 있다. |
| **참고하고 싶은 디자인(선택)** | "이 사이트처럼 만들어 줘"라고 보여 줄 만한 웹사이트 링크가 있으면 결과물이 훨씬 또렷해진다. |

### 1단계. 프로젝트 폴더 만들기

바탕화면에 `웹사이트`라는 이름으로 새 폴더를 하나 만든다. 앞으로 이 폴더 안에서 모든 작업이 이뤄진다.

### 2단계. CLAUDE.md로 작업 지침 정해 주기

`웹사이트` 폴더 안에 `CLAUDE.md`라는 파일을 만들고, 에이전트가 따를 작업 원칙과 디자인 방향을 적어 둔다. 이렇게 해 두면 매번 같은 요청을 반복하지 않아도 된다.

```markdown
# 프로젝트 소개
Next.js로 만드는 회사(또는 개인) 소개 웹사이트다.

## 작업 원칙
1. 코드를 쓰기 전에 어떻게 만들지 먼저 생각하고 계획을 간단히 말한다.
2. 꼭 필요한 기능만 최소한으로 구현한다. 요청하지 않은 기능은 추가하지 않는다.
3. 문제가 생긴 부분만 고친다. 멀쩡한 코드는 건드리지 않는다.
4. 작업이 끝나면 로컬에서 실행하는 방법을 안내한다.

## 디자인 가이드
- 깔끔하고 여백이 넉넉한 레이아웃을 우선한다.
- 모바일 화면에서도 깨지지 않도록 반응형으로 만든다.
- 과한 장식보다는 읽기 편한 구조를 우선한다.
```

### 3단계. 클로드 코드 열고 프로젝트 시작하기

터미널에서 방금 만든 `웹사이트` 폴더로 이동해 클로드 코드를 실행한다. 처음 사용한다면 다음과 같이 준비한다.

```bash
# 클로드 코드 설치 (최초 1회)
npm install -g @anthropic-ai/claude-code

# 웹사이트 폴더로 이동해서 실행
cd Desktop/웹사이트
claude
```

### 4단계. 웹사이트 제작 요청하기

아래 프롬프트를 복사해서, 괄호 부분을 자신의 상황에 맞게 바꾼 다음 클로드에게 전달한다. 참고하고 싶은 사이트가 있다면 링크도 함께 전달한다.

```text
Next.js로 "(웹사이트/회사 이름)"의 공식 웹사이트를 만들어 줘.

요구 사항:
1. 이 회사(또는 나)는 (한 줄로 무슨 일을 하는 곳인지 설명)이야.
2. 디자인은 이 사이트를 참고해 줘: (참고하고 싶은 사이트 링크, 없으면 생략)
3. 상단에는 (원하는 메뉴, 예: 소개, 서비스, 문의하기) 버튼이 있었으면 좋겠어.
4. "문의하기" 버튼을 누르면 (원하는 동작, 예: 이메일 주소로 연결)되게 해 줘.
5. 전체적으로 (원하는 분위기, 예: 깔끔하고 전문적인 느낌)으로 만들어 줘.
6. 나중에 Vercel에 배포할 수 있도록 Next.js 구조로 만들어 줘.
7. 다 만들었으면 로컬에서 실행해서 브라우저로 확인할 수 있게 안내해 줘.
```

엔터를 누르면 클로드가 계획을 세우고 코드를 작성하기 시작한다. 프로젝트 규모에 따라 몇 분에서 십여 분 정도 걸릴 수 있다.

### 5단계. 로컬에서 확인하고 수정 요청하기

코드 작성이 끝나면 클로드가 실행 방법을 안내해 준다. 보통 아래 명령으로 로컬 서버를 띄운다.

```bash
npm install
npm run dev
```

터미널에 뜬 `http://localhost:3000` 같은 주소를 브라우저에 열어서 실제 화면을 확인한다. 마음에 안 드는 부분이 있으면 바로 요청하면 된다. 예를 들면 이런 식이다.

```text
상단의 "회사 소개" 문구를 지워 줘.
"문의하기" 버튼 색상을 좀 더 눈에 띄게 바꿔 줘.
```

이 수정-확인 과정을 마음에 들 때까지 반복한다.

### 6단계. GitHub에 코드 올리기

1. GitHub에서 새 저장소를 하나 만든다. 이름은 `website` 정도로 하고, 비공개(Private)로 설정하는 것을 권장한다.
2. 만들어진 저장소의 주소(URL)를 복사한다.
3. 클로드에게 이렇게 요청한다.

```text
이 저장소에 지금까지 작성한 코드를 올려 줘: (여기에 저장소 URL)
```

클로드가 깃 설정과 커밋, 푸시를 대신 처리해 준다. 이렇게 코드를 클라우드에 올려 두면, 내 컴퓨터에 문제가 생겨도 다시 받아서 이어서 작업할 수 있다.

### 7단계. Vercel에 배포하기

1. Vercel에 GitHub 계정으로 로그인한다.
2. "새 프로젝트 추가(Add New Project)"를 누르고, 방금 올린 GitHub 저장소를 선택해서 가져온다(Import).
3. 설정은 대부분 기본값 그대로 두고 **배포(Deploy)** 버튼을 누른다.
4. 1~2분 정도면 배포가 끝나고, `(이름).vercel.app` 형태의 주소가 생긴다. 이 링크를 다른 사람에게 보내면 누구나 접속할 수 있다.

### 8단계. 수정하면 자동으로 다시 배포된다

한번 GitHub와 Vercel을 연결해 두면, 이후로는 수정이 훨씬 간단해진다.

1. 클로드에게 수정할 내용을 요청한다.
2. 수정이 끝나면 "변경된 코드를 GitHub에 올려 줘"라고 요청한다.
3. Vercel이 GitHub 저장소의 변경을 자동으로 감지해서 몇십 초 안에 재배포한다. 같은 주소로 다시 들어가 보면 바뀐 내용이 바로 반영되어 있다.

즉 처음 배포 이후로는 "클로드에게 수정 요청 → GitHub에 올리기"만 반복하면, 배포는 자동으로 따라온다.

## 3부. 자주 막히는 부분

**Q. 클로드가 만든 코드에 오류가 난다면?**
오류 메시지를 그대로 복사해서 클로드에게 붙여넣고 "이 오류가 나는데 고쳐 줘"라고 요청하면 된다. 원인을 직접 분석할 필요 없이, 에이전트가 오류 메시지를 읽고 스스로 수정한다.

**Q. GitHub나 Vercel 가입·연동에서 막히면?**
막히는 화면을 그대로 캡처하거나 상황을 설명해서 클로드에게 물어보면 된다. "GitHub 로그인이 안 되는데 어떤 버튼을 눌러야 해?"처럼 구체적으로 물으면 다음 단계를 안내해 준다.

**Q. 처음부터 완벽한 결과물이 안 나온다면?**
당연한 일이다. 한 번에 완성되길 기대하기보다, "이 부분은 이렇게 바꿔 줘"를 여러 번 반복하는 것을 기본 과정으로 생각하면 편하다.

**Q. 민감한 정보를 다루는 사이트라면?**
비밀번호, 결제 정보, 사내 데이터처럼 민감한 내용을 다루는 프로젝트라면, 작업을 시작하기 전에 어떤 정보를 코드에 직접 넣지 않을지(환경 변수로 분리할지) 미리 생각해 두는 것이 안전하다. 간단한 소개 웹사이트 수준에서는 크게 신경 쓰지 않아도 된다.

## 마무리

정리하면, 웹사이트를 만드는 데 필요한 것은 복잡한 프로그래밍 지식이 아니라 다음 세 가지였다.

1. **무엇이 필요한지 아는 것** — 에이전트, 바이브 코딩, 서버·배포, GitHub 같은 기본 개념.
2. **정확하게 요청하는 것** — 클로드에게 무엇을 어떻게 만들어 달라고 구체적으로 전달하는 프롬프트.
3. **차근차근 따라가는 것** — 폴더 생성 → 제작 요청 → 로컬 확인 → GitHub 업로드 → Vercel 배포.

이 흐름(폴더 만들기, 지침서 작성, 요청, 확인, GitHub, Vercel)은 다음에 만들 것이 챗봇이든 다른 서비스든 거의 그대로 반복된다. 다음 글 [나만의 챗봇 만들기]({{< ref "나만의-챗봇-만들기" >}})에서는 여기에 AI 모델과 실시간 검색 기능을 더해, 질문에 답해 주는 나만의 챗봇을 만들어 본다.
