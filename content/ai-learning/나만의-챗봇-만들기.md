코딩을 전혀 몰라도 괜찮다. 이 글은 클로드(Claude)에게 "이렇게 만들어 줘"라고 요청하는 방식으로, 실제로 작동하는 나만의 챗봇 웹사이트를 처음부터 끝까지 만들어 보는 글이다. 코드는 클로드가 쓰고, 우리는 무엇을 만들지 결정하고 방향을 잡아 주면 된다. 이런 개발 방식을 흔히 **바이브 코딩**이라고 부른다.

먼저 챗봇이 어떻게 작동하는지 핵심 개념 다섯 가지를 짧게 짚고, 그다음 실제로 손을 움직여 챗봇을 만들고 인터넷에 배포까지 해 본다.

---

## 1부. 챗봇을 만들기 전에 알아야 할 것들

### 1-1. LLM이란 무엇인가

클로드나 GPT 같은 인공지능은 흔히 **LLM**(거대 언어 모델, Large Language Model)이라고 불린다. LLM은 질문의 의미를 이해해서 사실을 조회해 주는 존재가 아니라, "이다음에 올 확률이 가장 높은 단어"를 하나씩 이어 붙여서 답을 만들어 내는 통계 기계에 가깝다.

예를 들어 LLM에게 "오늘 서울 날씨 어때?"라고 물으면 "오늘 서울은 맑습니다" 같은 그럴듯한 문장을 만들어 낼 수는 있지만, 이 모델 자체는 실제 기상 데이터를 가지고 있지 않다. 그래서 순수한 LLM만으로는 실시간 정보에 정확하게 답할 수 없다.

### 1-2. 챗봇 = LLM + 도구

그런데 우리가 실제로 쓰는 챗봇 서비스는 날씨도 알려 주고 최신 뉴스도 요약해 준다. 이게 가능한 이유는 LLM 하나만 쓰는 게 아니라, **LLM에 외부 도구를 연결**해서 쓰기 때문이다.

구조는 이렇다.

1. 사용자가 질문을 입력한다.
2. 그 질문에 실시간 정보나 계산이 필요하다고 판단되면, LLM이 연결된 도구(검색, 계산기 등)를 호출한다.
3. 도구가 가져온 결과를 LLM에게 다시 전달한다.
4. LLM이 그 결과를 바탕으로 사람이 읽기 좋은 답변 문장을 만든다.

즉 챗봇이라는 건 **"언어를 다루는 엔진(LLM)" + "실제로 일을 해 오는 도구들"**이 결합된 시스템이다.

### 1-3. API와 API 키

LLM은 연산량이 매우 커서 개인 컴퓨터나 무료 배포 서버에서 직접 돌리기 어렵다. 그래서 우리가 만드는 웹사이트는 LLM을 직접 들고 있지 않고, LLM을 제공하는 회사(앤트로픽 등)의 서버에 "이 질문에 대한 답을 만들어 줘"라고 요청만 보낸다. 이렇게 **프로그램끼리 정해진 규칙에 따라 요청과 응답을 주고받는 방식**을 **API**(Application Programming Interface)라고 한다.

이때 "지금 요청하는 사람이 누구인지, 얼마나 썼는지"를 구분하기 위해 일종의 출입증 같은 값을 발급받는데, 이것이 **API 키**다. API 키는 비밀번호와 같다. 유출되면 다른 사람이 내 계정의 사용량(=내 비용)으로 API를 쓸 수 있으므로, 코드 저장소나 댓글, 공개된 곳에 절대 올리면 안 된다.

### 1-4. MCP — 챗봇에 도구를 연결하는 표준 규격

LLM에 도구를 연결하는 방법은 여러 가지가 있지만, 요즘 가장 널리 쓰이는 방식이 **MCP**(Model Context Protocol)다. "모델에게 지금 필요한 맥락(정보)을 전달하는 약속된 방법"이라고 생각하면 된다.

MCP 서버를 하나 연결하면 LLM이 할 수 있는 일이 늘어난다. 예를 들어 실시간 웹 검색 MCP를 연결하면, 모델 학습 시점 이후에 일어난 최신 뉴스도 검색해서 답변에 반영할 수 있게 된다. (모든 LLM은 특정 시점까지의 데이터로 학습되었기 때문에, 그 이후의 일은 도구 없이는 알지 못한다. 이 학습 마감 시점을 **지식 컷오프**라고 부른다.)

### 1-5. 스킬 파일(CLAUDE.md) — 에이전트에게 주는 작업 지침서

클로드 코드(Claude Code)처럼 코드를 작성해 주는 에이전트에게 작업을 시킬 때, 매번 같은 지시를 반복하는 대신 **작업 방식을 적어 둔 문서 하나를 프로젝트 폴더에 넣어 두는 방법**이 있다. 이 문서를 보통 `CLAUDE.md`라는 이름의 마크다운 파일로 만든다.

이렇게 해 두면 에이전트가 이 폴더에서 작업할 때마다 이 지침을 자동으로 참고한다. "디자인은 이런 느낌으로 해 줘", "코드는 이런 원칙으로 짜 줘" 같은 반복적인 요구 사항을 한 번만 적어 두면 되는 것이다.

## 2부. 실전 — 클로드로 나만의 챗봇 만들기

### 준비물

| 항목 | 설명 |
|---|---|
| **클로드 코드(Claude Code)** | 터미널에서 클로드에게 코드를 작성하고 실행시킬 수 있는 도구. 설치 없이 익숙하지 않다면 claude.ai의 대화창에서 똑같은 과정을 안내받으며 따라가도 된다. |
| **앤트로픽 API 키** | console.anthropic.com에서 회원 가입 후 발급. 챗봇이 실제로 답변을 생성할 때 필요하다. |
| **(선택) 실시간 검색 도구 API 키** | 최신 정보 검색 기능까지 넣고 싶다면, 실시간 웹 검색을 제공하는 MCP 서비스(예: Tavily)에 가입해 키를 받는다. 매달 일정량까지는 무료로 제공하는 서비스가 많다. |
| **GitHub 계정** | 완성된 코드를 저장하고 배포 서비스와 연결하는 데 쓴다. |
| **Vercel 계정** | 완성된 웹사이트를 무료로 인터넷에 올려 주는 배포 서비스. GitHub 계정으로 바로 가입할 수 있다. |

> API 키는 가입 직후 바로 발급된다. 발급받은 키는 메모장 등에 잠시 적어 두고, 작업이 끝나면 코드에는 직접 적지 말고 나중에 설명할 **환경 변수**라는 곳에만 넣는다.

### 1단계. 프로젝트 폴더 만들기

바탕화면에 `챗봇`이라는 이름으로 새 폴더를 하나 만든다. 앞으로 이 폴더 안에서 모든 작업이 이뤄진다.

### 2단계. CLAUDE.md로 작업 지침 정해 주기

방금 만든 `챗봇` 폴더 안에 `CLAUDE.md`라는 파일을 하나 만들고, 아래처럼 작성해 둔다. 직접 타이핑해도 되고, 클로드에게 "이런 내용으로 CLAUDE.md를 만들어 줘"라고 요청해도 된다.

```markdown
# 프로젝트 소개
Next.js와 Claude API로 만드는 개인용 AI 챗봇 웹사이트다.

## 작업 원칙
1. 코드를 쓰기 전에 어떻게 만들지 먼저 생각하고 계획을 간단히 말한다.
2. 꼭 필요한 기능만 최소한으로 구현한다. 요청하지 않은 기능은 추가하지 않는다.
3. 문제가 생긴 부분만 고친다. 멀쩡한 코드는 건드리지 않는다.
4. 사용자가 원하는 결과(목적)를 기준으로 판단해서 작업한다.

## 디자인 가이드
- 채팅 화면은 메신저 앱처럼 말풍선 형태로, 간결하고 깔끔하게 만든다.
- 모바일 화면에서도 깨지지 않도록 반응형으로 만든다.
- 과한 장식보다는 읽기 편한 여백과 글자 크기를 우선한다.
```

이 네 가지 작업 원칙(먼저 생각하기, 단순하게, 필요한 부분만, 목적 중심)은 많은 개발자들이 에이전트에게 코드를 맡길 때 공통으로 당부하는 내용이다. 이걸 지침서로 미리 줘 두면, 매번 "간단하게 해 줘"라고 반복해서 말하지 않아도 된다.

### 3단계. 클로드 코드 열고 프로젝트 시작하기

터미널(또는 클로드 코드 앱)에서 방금 만든 `챗봇` 폴더를 프로젝트로 연다. 처음 사용한다면 다음과 같이 준비한다.

```bash
# 클로드 코드 설치 (최초 1회)
npm install -g @anthropic-ai/claude-code

# 챗봇 폴더로 이동해서 실행
cd Desktop/챗봇
claude
```

실행되면 클로드가 대화창 형태로 뜬다. 여기에 CLAUDE.md를 읽었는지, 그리고 무엇을 만들고 싶은지 순서대로 요청하면 된다.

### 4단계. 챗봇 제작 요청하기

아래 프롬프트를 그대로 복사해서, 괄호 부분만 자신의 상황에 맞게 바꾼 다음 클로드에게 전달한다.

```text
Next.js로 "나만의 AI 챗봇"이라는 이름의 간단한 웹사이트를 만들어 줘.

요구 사항:
1. 사용자가 채팅창에 메시지를 입력하면, Claude API를 호출해서 답변을 생성해 줘.
   - API 키는 환경 변수 ANTHROPIC_API_KEY로 읽어 와서 사용하고,
     코드 안에 직접 키 값을 적지 마.
   - 모델은 claude-sonnet-5-5를 사용해 줘.
2. 최신 뉴스나 실시간 정보가 필요한 질문에는 실시간 웹 검색 도구를
   MCP로 연결해서 답하게 해 줘. (이 부분은 선택 사항이야. 먼저 기본
   챗봇부터 완성하고, 되면 이 기능을 추가해 줘.)
3. 채팅 화면은 ChatGPT처럼 심플한 형태로 만들어 줘.
4. 나중에 Vercel에 배포할 수 있는 구조로 만들어 줘.
5. 다 만들었으면 로컬에서 실행해서 브라우저로 확인할 수 있게 안내해 줘.
```

엔터를 누르면 클로드가 계획을 세우고 코드를 작성하기 시작한다. 프로젝트 규모에 따라 몇 분 정도 걸릴 수 있으니 기다리면 된다. 중간에 "앤트로픽 API 키를 입력해 줘"라고 물으면, 미리 발급받은 키를 붙여넣으면 된다. (이 키는 다음 단계에서 설명할 **환경 변수** 파일에 저장되며, 깃허브에는 올라가지 않는다.)

### 5단계. 로컬에서 먼저 테스트하기

코드 작성이 끝나면 클로드가 실행 방법을 안내해 준다. 보통 아래와 같은 명령으로 로컬 서버를 띄운다.

```bash
npm install
npm run dev
```

터미널에 뜬 `http://localhost:3000` 같은 주소를 브라우저에 열어서, 실제로 메시지를 보내고 답변이 돌아오는지 확인한다. 디자인이 마음에 안 들거나 불필요한 요소가 보이면, "이 부분은 이렇게 바꿔 줘"라고 클로드에게 바로 요청하면 된다. 이 수정-확인 과정을 마음에 들 때까지 반복한다.

### 6단계. GitHub에 코드 올리기

1. GitHub에서 새 저장소(repository)를 하나 만든다. 이름은 `chatbot` 정도로 하고, 비공개(Private)로 설정하는 것을 권장한다.
2. 만들어진 저장소의 주소(URL)를 복사한다.
3. 클로드에게 이렇게 요청한다.

```text
이 저장소에 지금까지 작성한 코드를 올려 줘: (여기에 저장소 URL)
```

클로드가 깃 설정과 커밋, 푸시를 대신 처리해 준다. 이때 API 키 같은 민감한 값은 자동으로 제외하고 올리므로, 저장소에는 코드만 올라간다.

### 7단계. Vercel에 배포하고 API 키 입력하기

1. Vercel에 GitHub 계정으로 로그인한다.
2. "새 프로젝트 추가(Add New Project)"를 누르고, 방금 올린 GitHub 저장소를 선택해서 가져온다(Import).
3. 배포 설정 화면 아래쪽에 **환경 변수(Environment Variables)** 입력란이 있다. 여기에 아까 발급받은 키를 입력한다.

| Key | Value |
|---|---|
| `ANTHROPIC_API_KEY` | 앤트로픽 콘솔에서 발급받은 키 |
| `TAVILY_API_KEY` | (실시간 검색 기능을 넣었다면) 발급받은 키 |

코드가 요구하는 환경 변수 이름이 이것과 다르게 나올 수도 있다. 그럴 때는 클로드에게 "Vercel에 배포할 건데 환경 변수에 뭘 입력해야 해?"라고 물어보면, 어떤 이름에 어떤 값을 넣으면 되는지 정확히 안내해 준다.

4. 값을 다 입력했다면 **배포(Deploy)** 버튼을 누른다. 1~2분 정도면 배포가 끝나고, 전 세계 어디서나 접속할 수 있는 주소가 생긴다.

### 8단계. 배포된 사이트에서 최종 확인

배포가 끝나면 나온 링크로 들어가서, 로컬에서 했던 것처럼 챗봇에 말을 걸어 본다. 실시간 검색 기능을 넣었다면, "오늘 주요 뉴스 알려 줘"처럼 최신 정보가 필요한 질문도 던져서 잘 작동하는지 확인한다.

## 3부. 자주 막히는 부분

**Q. 클로드가 만든 코드에 오류가 난다면?**
오류 메시지를 그대로 복사해서 클로드에게 붙여넣고 "이 오류가 나는데 고쳐 줘"라고 요청하면 된다. 직접 원인을 분석할 필요 없이, 에이전트가 오류 메시지를 읽고 스스로 수정한다.

**Q. API 키가 유출된 것 같다면?**
앤트로픽 콘솔과 사용한 MCP 서비스(예: Tavily)의 대시보드에서 기존 키를 즉시 삭제하고 새 키를 발급받는다. 그다음 Vercel 프로젝트의 환경 변수 값도 새 키로 교체하고 다시 배포한다.

**Q. 비용이 걱정된다면?**
API는 쓴 만큼만 과금되는 종량제다. 처음에는 회원 가입 시 제공되는 소액의 무료 크레딧 안에서 테스트해 보고, 모델도 가볍고 저렴한 쪽을 선택하면 비용 부담 없이 연습할 수 있다. 사용량은 앤트로픽 콘솔에서 언제든 확인할 수 있다.

**Q. 실시간 검색 기능은 꼭 넣어야 하나?**
아니다. 검색 기능 없이도 일반적인 대화형 챗봇은 충분히 만들 수 있다. 다만 "오늘 날씨", "최신 뉴스"처럼 실시간 정보가 필요한 질문에는 답하지 못한다는 한계가 있다. 처음에는 검색 없이 기본 챗봇부터 완성하고, 익숙해지면 MCP 도구를 하나씩 추가해 나가는 방식을 권한다.

---

## 마무리

정리하면, 챗봇을 만드는 데 필요한 것은 복잡한 프로그래밍 지식이 아니라 다음 세 가지였다.

1. **무엇이 필요한지 아는 것** — LLM, API, MCP, 작업 지침서(CLAUDE.md) 같은 기본 개념.
2. **정확하게 요청하는 것** — 클로드에게 무엇을 어떻게 만들어 달라고 구체적으로 전달하는 프롬프트.
3. **차근차근 따라가는 것** — 폴더 생성 → 개발 요청 → 로컬 확인 → GitHub 업로드 → Vercel 배포.

이제 기본 뼈대는 완성되었으니, 여기서 더 나아가 "내 문서나 데이터를 기반으로 답하는 챗봇"이나 "로그인 기능이 있는 챗봇"처럼 응용 단계로 넘어가 볼 수 있다. 같은 방식으로 클로드에게 원하는 기능을 설명하고 요청하면 된다.
